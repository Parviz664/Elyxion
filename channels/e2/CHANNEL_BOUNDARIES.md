# CHANNEL_BOUNDARIES

## Boundary evolution

### v1.0–v1.2
E2 boundary was:
**think across several candidate paths, but do not execute**.

It could:
- generate/rank 3–7 variants;
- model risks/counterfactuals;
- recommend one.

It could not:
- modify locked A2/E-Prime/E0/D0 context;
- build/test/package/release;
- authorize runtime promotion;
- override D1 harm guards.

### v2.1
Boundary changes to:
**translate one primary path into engine contracts + E5 affordance structure**.

New prohibitions:
- no portfolio by default;
- no metric/scoring axis;
- no meaning-lane engine tokens;
- no taskification;
- no engine vocabulary promotion into meaning.

### v2.2
Boundary narrows:
**engine-contract translation + bounded routes**, with E3 owning build convergence.

### v2.3
Boundary purification:
- D-family no longer mandatory E2 core;
- E5 affordance output removed from E2 identity/core;
- internal fidelity/temptation policing demoted to optional external overlays;
- E2 is pure E-mainline translation/bounded-route/maturity/handoff.

## Current hard edge

The moment a problem asks:
- “Which exact build sequence do we execute?” → E3.
- “Is this ready to proceed/release?” → E4.
- “What should the human click/do next?” → E5.
- “What happened in runtime?” → E6.

E2 stops before all of those.
