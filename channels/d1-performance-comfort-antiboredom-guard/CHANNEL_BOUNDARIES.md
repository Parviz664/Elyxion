# CHANNEL BOUNDARIES

## Authority boundary

D1 owns guard decisions inside its contract.

It does **not** own D0 truth, D-line canon mutation, gameplay/lore authorship, or runtime implementation.

## Current hard non-scope (v2.4)

- monetization strategy;
- lore narrative;
- marketing;
- pricing;
- any E-channel integration;
- mutation of D0 locked fields;
- inference of missing D-registry items.

## No-inference boundary

Missing/untrusted evidence does not become zero, safe, green, or assumed-pass.

Correct semantic state is:

**BLOCK / UNKNOWN until required evidence exists.**

This is especially important because historical assistant reports sometimes filled unmeasured numeric fields with `0`. That is not equivalent to unknown.

## Canon boundary

D1 may protect and gate canon-constrained behavior.

D1 may not:

- rewrite the authored game meaning;
- strengthen a candidate into canon;
- silently upgrade dependency versions;
- merge historically isolated trace lanes;
- self-certify that implementation matches intent.

## Human-state boundary

D1 uses psychotype/segment language in the supplied contract for comfort and harm guarding.

The recovery does not elevate this into a medical diagnostic system.

No recovered D1 authority permits diagnosis or coercive behavior shaping.

## E-channel boundary

Historical:

- v2.1/v2.2 contain E-Prime/E0/E1/E4 relationships.

Current:

- v2.4 explicitly removes all E dependencies and lists `any_E_channel_integration` as non-scope.
- attempt to inject E-channel logic/refs is an anti-injection reject condition.

Therefore an E reference is not globally "wrong in D1 history"; it is **historically valid but currently forbidden**.

## P/A boundary

No evidence supports classifying D1 as P or A.

No direct D1 P↔A bridge packet is recovered.

Status: UNKNOWN / NOT EVIDENCED.

## Adjacent-channel confusion risks

D1 can be confused with:

- D0: source of locked D-line context; D1 does not replace it.
- D2: downstream onboarding/optimizer function; D1 supplies guard conditions, not D2 optimization.
- D3: telemetry brain; D1 exports fields but is not the telemetry store.
- D4: experiment orchestrator; D1 constrains experiments but does not own experimental orchestration.
- D5/D6: audio/visual feel truth guards; D1 exports higher-level audio/visual comfort constraints.
- E implementation channels: historical interfaces existed, but current v2.4 forbids E dependencies.

## Release boundary

A D1 PASS is only a D1 gate result.

The supplied truth constraint explicitly says D1 does not guarantee market-scale adoption.
