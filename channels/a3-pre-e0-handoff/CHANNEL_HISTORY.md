# CHANNEL_HISTORY

A3 did not begin in its current v2.2 form.

## Earliest strongly recovered form — v1.0

The earliest full contract recovered here is ELYX_A3_CHANNEL_SPEC_V1_0_MASTER.

Technical ID: A3_CANONICAL_DREAM_BINDING_AND_E0_PACKAGING.
Human name: A3 Канал Канонической Сцепки Мечты и Упаковки для E0.

Its mission was an immutable A2→E0 bridge: ingest A2_SYSTEMS_MAP, preserve dream semantics 1:1, validate E-Prime lock alignment, carry trace/hash evidence, emit A2_COPY_PASTE_HANDSHAKE_PACKET and A2_COMPLETION_DELTA_PACKET, and prepare downstream carry for D0/E1/D1.

The opening direct user instruction was:
“Работать строго по контракту А3!”

That sentence is AUTHOR_RAW. The large JSON contract is USER_SUPPLIED_ARTIFACT; line-by-line authorship is not proven.

## v1.1 — sealed bundle hardening

v1.1 retained the E-Prime-dependent model but required one sealed upstream bundle containing A2 + E-Prime lock. It added semantic non-rewrite judges, prompt-injection hardening, E3.5 manifest output and anti-deadlock behavior.

An earlier assistant execution had emitted PASS_WITH_CONSTRAINTS after only A2 was supplied despite missing independent E-Prime evidence. That execution is preserved as error/practice evidence, not owner canon.

## v1.2 — hash compute moves inside A3

v1.2 kept the sealed A2+E-Prime bundle requirement but made A3 compute SHA-256 itself when raw payload objects were available. The supplied patch explicitly frames this as operator-friction reduction and removal of manual hash assembly.

## v1.3 snapshot A — major architectural reversal

v1.3 removed E-Prime from A3.

A3 became an A-only notary/seal:
A2 + Canon Source Packet -> A3 -> E0,
while E-Prime was to reach E0 separately from E6/E-lane.

This is a real route reversal:
E-Prime validation inside A3 -> E-Prime forbidden inside A3.

## v1.3 snapshot B — same semver, different contract state

A later user-supplied v1.3 artifact still used semver 1.3.0 but materially revised the fidelity model:
- bounded fidelity cap instead of absolute-style promise,
- no-drop manifest,
- hard vs soft canon-source distinctions,
- explicit denial of 100% guarantee.

Recovery preserves both snapshots. It does not pretend one silently replaced the other without a versioning defect.

## v1.4 — direct A2-only fast path

v1.4 introduced two automatic ingest modes:
- FULL_CANON_CARRY,
- A2_ONLY_SEAL.

The operator could paste one A2 payload directly. Missing canon source became explicit MISSING_UPSTREAM rather than a mandatory block, with a lower audit cap.
