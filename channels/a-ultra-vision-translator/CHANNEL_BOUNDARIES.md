# CHANNEL_BOUNDARIES

## Canon boundary

CANON may contain only grounded claims supported by p5_spine_refined and/or preserved vision text excerpts when available.

No detail leap.

## Poetic boundary

If metaphorical wording cannot safely become a factual claim, v4.3 stores it as direct quote under `poetic_claims_as_quotes`.

Metaphor is not automatically a world law.

## DreamVault boundary

DreamVault role:
expression / tone / image / rhythm reinforcement only.

Allowed downstream use:
- P4: feel-selection hints only
- P5: presentation compression only
- A1: tone-only
- E*: tone-only

Forbidden as logic source:
- A2
- A3
- A0 binding
- E* logic

## Implementation boundary

A-Ultra may state what must remain semantically stable.

It may not state how Unreal/engine/algorithm/UI/economy/progression should implement that stability unless already explicit in source and lawfully in scope.

## Authority boundary

A-Ultra does not:
- route the whole project;
- decide build readiness;
- write A1 architecture;
- execute E implementation;
- resolve missing source by invention.

## Transport boundary

v4.3 requires a single JSON root and no extra text outside it. Forwarding uses `next_message_to_next_agent`.

## P5 boundary

P5 must not become a hidden causal rewriter. Missing backbone/logic-patch evidence is handled conservatively.

## P4 direct-input boundary

P4 direct input is historically observed but contractually unresolved because v4.3 does not list a P4 source type.

Do not silently promote it to formal support.
