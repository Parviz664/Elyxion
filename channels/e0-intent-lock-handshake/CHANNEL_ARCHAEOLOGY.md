# CHANNEL ARCHAEOLOGY

## Archaeological conclusion

E0 did not begin as the v1.5 Dual-Lock Binder.

The earliest recovered E0 is a strict mandatory ingress gate whose central law was:
"No downstream work starts without current E-Prime truth plus validated A2 response."

It required:
- eprime_input_packet
- a2_response_packet

It locked E-Prime, requested A2, validated them together, then intended to release downstream.

The channel then repeatedly hit a practical problem: semantically useful A2 material did not always arrive in the exact handshake shape/field location expected by E0. Actual BLOCK results occurred even when a rich A2 systems map existed.

The most explicit diagnosis appears in the supplied v1.2 patch:
"A2 fields were valid semantically but not found in strict expected locations."

E0 then evolved in two directions at once.

Fidelity/no-mutation:
- A2 copy-paste only;
- dream immutability;
- hash/byte/semantic checks;
- no inference;
- registry+seal.

Deadlock reduction:
- PASS_WITH_CONSTRAINTS;
- no_ideal_waiting;
- safe autofill from locked values only;
- completion-delta closure;
- phased planning before runtime closure.

v1.3 widened E0 into a cross-channel synchronization gate for E/D channels and introduced E4/D4 psycho-operational seed requirements.

v1.4 added registry+seal no-inference and prompt-injection hardening. Under that contract an A3 A2-only seal was insufficient because registry+seal were absent.

v1.5 explicitly changed the axis of the channel:
- E0 becomes two-input;
- A2 is no longer the primary direct ingress;
- dream enters through A3;
- kernel truth enters through E6;
- Planning Dispatch is separated from Runtime Promotion.

Latest recovered role:
E6 kernel lock + A3 dream lock -> E0 bind -> one locked handle -> planning route; runtime promotion remains closed until closure proofs.

Do not back-project v1.5 into v1.1.
