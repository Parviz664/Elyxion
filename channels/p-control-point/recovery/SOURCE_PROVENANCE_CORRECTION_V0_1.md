# SOURCE_PROVENANCE_CORRECTION_V0_1

Status: `PROVENANCE_CLASSIFICATION_CORRECTION`

Applies to recovery files created before this record that used phrases such as:

- `DIRECT_OWNER_CHAT_ARTIFACT_RECOVERY`
- `owner-origin artifact`

## 1. Problem

A chat artifact can be:

1. written directly by the owner;
2. pasted/supplied by the owner but originally generated by an assistant;
3. collaboratively evolved;
4. copied from another source.

The fact that an artifact appears in a user message proves:

`SUPPLIED_BY_OWNER_IN_CHAT`

It does **not** automatically prove:

`AUTHORED_BY_OWNER`.

## 2. Corrected provenance model

Future recovery records must separate:

- `supplied_by`
- `artifact_origin`
- `owner_acceptance_status`
- `source_timestamp`
- `content_recovery_fidelity`

Preferred classes:

### USER_SUPPLIED_CHAT_ARTIFACT

The owner supplied/pasted the artifact in chat.

This does not claim who originally authored every line.

### OWNER_EXPLICIT_DECISION

The owner directly states a decision in their own message.

### PERSISTENT_RAW_FILE

The artifact exists in the preserved file corpus.

### ASSISTANT_INTERPRETATION

Assistant-generated explanation only.

## 3. Correction to previous records

For P0/P1 artifacts recovered from February–March chats, the safest current classification is:

`USER_SUPPLIED_CHAT_ARTIFACT`

unless a specific line is separately proven to be direct owner wording.

The October 6 Decision C remains:

`OWNER_EXPLICIT_DECISION`

because the owner directly selected C in the current conversation.

## 4. Authority consequence

This correction changes provenance precision, not the recovered structural facts.

For example:

- a user-supplied P0 v2.4 artifact can still prove that the working architecture in that conversation used `NO_-P1`;
- it must not automatically be described as text personally authored line-by-line by the owner.

## 5. New failure class

`PROVENANCE_OVERCLAIM`

Trigger:

source evidence is stronger in wording than the actual provenance supports.

Examples:

- "owner authored" when only "owner supplied" is proven;
- "raw source" when only a recovered chat summary exists;
- "exact artifact bytes" when only semantic recovery exists.

## 6. Supersession note

This record supersedes only the **provenance labels** in earlier recovery files.

It does not delete or rewrite those files.

Their structural findings remain subject to the evidence ceiling stated in each record.
