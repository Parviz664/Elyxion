# CHANNEL_ROLE_CORE

## Core mission

P4 receives canonical-ID candidate material from P3 and performs selection/final-cut work without altering candidate semantics.

Current mission recovered from v3.2.2:
- shortlist/spine of maximum feel potential;
- reserves;
- montage/rhythm annotation;
- role-aware backbone map;
- strict causality;
- observables-first selection;
- late-bridge anti-overcompression;
- terminal-mass control.

## Receive

Required current conceptual input:
- task_id;
- stage_scope;
- source_identity;
- feel_goal_profile;
- candidate_items.

Candidate identity:
- B### canon IDs;
- source order;
- `line`;
- confidence_tag;
- micro_transition_tag;
- feel tags as secondary/alias evidence;
- `depends_on`;
- optional semantic fingerprint;
- optional upstream binding refs.

## Transform authority

P4 may:
- preflight validate;
- compute editorial-only priority;
- assign P4 structural roles;
- build dependency closure;
- select in strict source order;
- repair observable-axis coverage through selection;
- no-guess trim provable duplicates;
- protect late speculative bridge mass;
- separate spine/reserves/meta handoff;
- report confidence and warnings;
- recommend a next channel.

## Non-authority

P4 may not:
- author new candidate content;
- rewrite P3 candidate line;
- invent missing dependencies;
- reorder P3;
- use scores as truth/world parameters;
- convert emotion labels into required ontology;
- add gameplay/UI/lore/progression;
- silently canonize;
- choose for the owner beyond the admitted `author_selects_ids_only` boundary;
- resolve global route conflicts.
