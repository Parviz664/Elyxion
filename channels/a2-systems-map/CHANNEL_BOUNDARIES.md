# CHANNEL BOUNDARIES

## Authority boundary

A2's authority is transformation-and-mapping authority over supplied canon-bearing material, not source-authority.

### Allowed boundary
SOURCE
→ trace-bound extraction
→ systems/dependencies/invariants/open questions
→ domino/conflict/fidelity/quarantine metadata
→ handoff/export.

### Forbidden boundary crossings
A2 must not:
- manufacture source material,
- resolve source contradictions,
- promote a candidate to canon,
- author implementation,
- write lore causality,
- convert uncertainty into certainty,
- make A3 decisions,
- treat E3.5 assembly as A2 validation.

## Canon boundary

A2 output can be CONTRACTED and merge-safe while still not being canon-promoting.
A2 is evidence-preserving middleware in the A-layer, not canon sovereignty.

## Meaning vs implementation boundary

Historical A1 packets originally mixed architecture/build vocabulary with meaning targets.
Later dual-view A1 v3.3 explicitly separates:
- `meaning_lane_view_v1`: semantic input for A2/A3,
- `implementation_lane_v1`: builder input.

Current safest A2 rule:
consume meaning lane for semantic mapping; keep implementation lane quarantined/separate.

## Conflict boundary

If anchors conflict:
- do not auto-resolve,
- retain conflict report,
- preserve both candidate invariants when required,
- route ambiguity forward.

## Dream boundary

DreamVault, when present:
- immutable echo,
- ref-only,
- no normalization.

DreamVault missing:

- never invent,
- never infer "dream lost",
- cap audit-grade guarantee.

## Proof boundary

Fidelity cap is a maximum claim allowed by contract conditions.
It is not a measured percentage of subjective dream preservation.
