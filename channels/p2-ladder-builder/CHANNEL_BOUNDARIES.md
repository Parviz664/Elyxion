# CHANNEL_BOUNDARIES

## Upstream boundary — P1

P2 may only use semantics P1 actually supplies or explicitly permits.

Forbidden seam failure:
inventing a causal bridge because the ladder "needs" one.

Required guard:
source binding + uncertainty + split/merge trace.

## Downstream boundary — P3

P2 hands structural semantics to P3.
P3 may render them, but may not strengthen missing semantics.

P2 must not pre-render poetic/final prose merely to make P3's job easier.

## Side boundary — A family

A-bridge is a compact derivative handoff, not a replacement for the P2->P3 main route.

Current v3.5 naming:
primary targets `A_ULTRA, A0, A1, A2, A3`;
legacy alias `A_MINUS_1`.

Exact direct production consumption by each A channel is not fully recovered.

## Author boundary

Author/owner retains:
- intent authority;
- canon authority;
- right to mark RAW/candidate/non-canon;
- right to select/override where contracts permit.

P2 has no authority to infer owner intent from assistant rationale.

## RAW boundary

Supplied-by-author != authored-by-author.

P2 must never overwrite source RAW.
Interpretation and ladder structure remain downstream artifacts.

## Implementation boundary

No evidence in this recovery proves a standalone P2 runtime implementation in code.
Current proof is contract + chat execution + neighboring durable docs.

Global route implementation remains blocked by P Control Point `HOLD_UNRESOLVED`.
